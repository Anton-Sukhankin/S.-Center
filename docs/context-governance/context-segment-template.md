# Шаблон области контекста

**Статус:** нормативный шаблон; копировать только применимые секции  
**Владелец:** [регламент управления контекстом](./README.md)  
**Обновлять:** при изменении обязательного минимума новой области

Шаблон используется после подтверждения самостоятельной области. Он не является требованием создавать полный комплект документов для каждой функции.

## Заголовок локального README

```markdown
# Индекс контекста «<название области>»

**Статус:** поддерживаемый локальный маршрут
**Область:** <граница функции, приложения, пакета или потока>
**Зрелость:** prototype | production | hybrid с пояснением
**Родительский индекс:** [<название>](<относительная ссылка>)
**Обновлять:** <события, меняющие маршруты или владельцев>
```

## Обязательные секции

### Назначение и граница

- пользовательский или системный результат;
- что входит и что не входит;
- соседние области и границы ответственности.

### Маршруты чтения

| Задача | Читать сначала | Затем при условии |
|---|---|---|
| Проверить current | Current-владелец и точное исполняемое evidence | Есть затронутый внешний потребитель |
| Изменить target | Target-владелец и current-baseline | Изменяется общая сущность или контракт |
| Реализовать | Активный пункт плана, target, current и исходник | Не установлен конкретный зависимый факт |
| Проверить происхождение | Поддерживаемый владелец | Требуется конкретное evidence |

Удалите строки, которые не относятся к области. Добавьте маршрут только для повторяемого типа задачи.

### Владение документами

| Артефакт | Состояние | Владеет | Обновлять когда |
|---|---|---|---|
| `<путь>` | current / target / transition / evidence | <один тип долговременных сведений> | <проверяемый триггер> |

### Реализация и проверки

- точные исходные каталоги или entry points;
- команды проверки;
- визуальные или ручные сценарии, если автоматической проверки недостаточно;
- ограничения зрелости.

### Правила роста и завершения

- условия выделения дочерней области;
- условия переноса общего факта родителю;
- условие удаления временного плана или evidence;
- действия при перемещении или удалении области.

## Условные документы

Создавайте документ только если у него есть самостоятельный владелец:

| Потребность | Возможный документ |
|---|---|
| Целевые продуктовые правила | `functional-context.md` |
| Подтверждённая текущая реализация | `technical-baseline.md` |
| Сущности, состояния и отношения | `domain-model.md` |
| Роли интерфейсных областей | `interface-map.md` |
| Связь требований, кода и проверок | `traceability-matrix.md` |
| Временный переход и прогресс | `implementation-plan.md` |
| Межфункциональный пользовательский результат | отдельный flow-контракт у общего владельца |

Не создавайте пустые документы, speculative API, роли, backend-контракты или production-гарантии.
