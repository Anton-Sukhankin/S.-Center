# Карта интерфейса цифровой шахматки

**Состояние документа:** долговременный владелец границ, ролей и связей интерфейсных областей; current и target отмечаются отдельно  
**Зрелость:** frontend-прототип  
**Основной читатель:** дизайнер, frontend-разработчик, тестировщик и агент реализации  
**Обновлять:** при добавлении, удалении, переносе или изменении роли интерфейсной области и её межкомпонентного контракта  
**Родительский индекс:** [контекст цифровой шахматки](./README.md)

Полные продуктовые правила принадлежат [functional-context.md](./functional-context.md), предметные данные — [domain-model.md](./domain-model.md), текущая композиция — [technical-baseline.md](./technical-baseline.md). Эта карта отвечает на вопросы «где находится корректировка», «какую роль играет область» и «с какими владельцами она связана».

## 1. Граница экрана

```text
S.Center shell
├─ Левая панель: поиск, дерево, выбор контекста
├─ Shell header: название раздела и путь объекта
└─ Основная область объекта
   ├─ Tabs: Информация / Работы / Шахматка
   └─ Вкладка Шахматка
      ├─ Статистика по дому
      ├─ Выбор группы и параметры группы
      └─ Работы
         └─ Accordion работы
            ├─ Header работы
            ├─ Левая легенда
            └─ Матрица этаж × секция
               ├─ Ячейки
               ├─ Меню статуса
               └─ Tooltip последнего изменения
```

Drawer «Настройки» является соседней областью shell. Полноэкранная работа временно меняет пространственное представление существующего аккордеона, но не создаёт новую сущность или второй экземпляр матрицы.

## 2. Реестр интерфейсных областей

| ID | Область и роль | Данные и действия | Видимый результат | Реализация и компоненты |
|---|---|---|---|---|
| `DC-UI-CONTEXT` | Левая навигация и путь объекта; задаёт контекст экрана | Выбор project/queue/object, сворачивание панели | Для объекта показываются путь и вкладки; для ветки — Empty State | `src/app.js`; Tree, Input, Button, Icon |
| `DC-UI-EMPTY` | Контекстная заглушка | Получает project/queue без `objectId` | Просит выбрать объект и скрывает объектные вкладки | `feature/digital-chessboard.js`; Empty State |
| `DC-UI-TABS` | Разделяет независимые объектные представления | Переключение «Информация / Работы / Шахматка» | Показывается один соответствующий panel | Feature; Tabs |
| `DC-UI-SUMMARY` | Сводка только выбранного объекта | Производная готовность объекта | Target: одна карточка готовности; current: дополнительно три планируемые карточки | Feature; Card, Icon, Tag |
| `DC-UI-GROUP` | Выбор одной группы и её сводные параметры | Модальный выбор, поиск, prev/next; название, готовность, период | Перестраивает список работ; сохраняет явную выбранность | Feature и groups data; Card, Modal, Input, Parameter Pair, Button |
| `DC-UI-WORK-LIST` | Вертикальная каталожная последовательность работ группы | Получает упорядоченные работы текущей группы | Заголовок «Работы» и последовательность аккордеонов | Feature; section + Accordion |
| `DC-UI-WORK-HEADER` | Идентифицирует работу и сохраняет параметры при сворачивании | Раскрытие; код, название, готовность, срок, подрядчик | Компактный header; 100% меняет левую индикацию | Feature; Accordion, Parameter Pair |
| `DC-UI-WORK-FULLSCREEN` | Изолирует одну существующую работу во viewport | maximize/minimize, Escape, prev/next работы | Тот же Accordion + Chessboard без потери состояния и scroll | Feature; Button, Icon, Accordion, Chessboard |
| `DC-UI-LEGEND` | Расшифровывает пять канонических состояний | Только чтение; получает общий реестр статусов | Постоянная левая колонка раскрытой работы без дополнительного поясняющего текста | Feature; продуктовая композиция swatch + text |
| `DC-UI-MATRIX` | Показывает выполнение работы по этажам и секциям | Двуосевая прокрутка, клавиатурная навигация, sticky-слои | Компактная сетка с header секций и колонкой этажей | Feature + общий Chessboard |
| `DC-UI-CELL` | Одна координата работы | Активация доступной ячейки | Открывает меню; disabled-позиция не интерактивна | Feature + Chessboard cell |
| `DC-UI-CELL-MENU` | Дискретный ввод состояния одной ячейки | Выбор одного из четырёх редактируемых статусов | Меняет ячейку, готовности и возвращает фокус | Feature; Menu и Button-примитивы |
| `DC-UI-CELL-HISTORY` | Показывает последнее демонстрационное изменение | Hover 1 секунда или `focus-visible` | Статус, автор, логин, дата и время | Feature; Tooltip |
| `DC-UI-SETTINGS` | Соседняя служебная конфигурация | Настройка видов и объектов | Не открывает шахматку и не заменяет дерево; шаблоны и источник плана не входят в активный контракт | `src/features/settings-drawer.js`; Drawer и form-компоненты |

## 3. Пространственные отношения

| Источник | Получатель | Контракт |
|---|---|---|
| `DC-UI-CONTEXT` | `DC-UI-TABS` или `DC-UI-EMPTY` | Только выбранный object открывает вкладки объекта; project/queue показывает заглушку. |
| Shell header | Tabs | Оба слоя последовательно закреплены сверху `.s-center-main`. |
| Tabs | Summary, Group, Work List | Контент шахматки расположен единым вертикальным потоком; сводка и группа не sticky. |
| Work Header | Legend и Matrix | Раскрытие показывает обе области, сворачивание скрывает их вместе. |
| Legend | Matrix | Легенда остаётся вне scroll-контейнера матрицы и не двигается по горизонтали. |
| Matrix | Work Header | Sticky-компенсация удерживает header работы и заголовки матрицы, не изменяя фактическую высоту аккордеона. |
| Cell | Cell Menu | Меню привязано к одной ячейке и закрывается при выборе, scroll или смене контекста. |
| Cell | Cell History | Tooltip не показывается одновременно с меню и не создаёт второй нативный `title`. |
| Work List | Work Fullscreen | В полноэкранный режим перемещается тот же экземпляр работы; после выхода восстанавливается список. |

Подробный технологически нейтральный nested-scroll контракт вынесен в [scroll-contract](./scroll-contract/README.md).

## 4. Граница общего компонента и продукта

| Механика общей базы | Продуктовое правило S.Center |
|---|---|
| Accordion раскрывает panel и управляет доступной связью | Какие параметры работы видны, когда работа считается завершённой и как выглядит полноэкранная композиция |
| Chessboard строит строки, колонки, ячейки и клавиатурную навигацию | Этажи, секции, пять статусов, готовность, sticky-поведение внутри списка работ |
| Menu управляет открытием, пунктами и фокусом | Какие статусы разрешены и как меняется одна ячейка |
| Tooltip управляет доступной подсказкой, задержкой и размещением | Состав сведений последнего изменения и правило задержки одной секунды |
| Card, Parameter Pair, Tabs, Button и Icon дают публичные примитивы | Состав сводки, параметры группы, вкладки объекта и действия перехода |

Продуктовое изменение не переносится в `component-library-transfer`, если оно не меняет общий контракт компонента для всех потребителей.

## 5. Маршрут корректировки по области

| Что изменяется | Сначала читать | Затем проверять |
|---|---|---|
| Контекст дерева и breadcrumb | `DC-UI-CONTEXT`, functional-context §2 | `src/app.js`, adapter, Empty State |
| Состав сводки объекта | `DC-UI-SUMMARY`, functional-context §4.1 | Feature, readiness и active plan |
| Выбор или параметры группы | `DC-UI-GROUP`, functional-context §4.2 | Groups data, modal и group calculations |
| Заголовок или lifecycle работы | `DC-UI-WORK-HEADER`, §4.3 | Accordion composition и baseline |
| Полноэкранный режим | `DC-UI-WORK-FULLSCREEN`, §4.3 | Feature и fullscreen acceptance |
| Легенда и цветовые статусы | `DC-UI-LEGEND`, domain-model §5 | Feature, Chessboard styles и доступные имена |
| Геометрия или scroll матрицы | `DC-UI-MATRIX`, functional-context §4.4 | Data geometry, Chessboard и scroll-contract |
| Ввод состояния | `DC-UI-CELL-MENU`, functional-context §5 | Domain transitions, Menu/Tooltip и readiness |
| Настройки | `DC-UI-SETTINGS`, functional-context §8 | Settings drawer; не расширять шахматку автоматически |

## 6. Условия роста карты

- Новая зона добавляется, если у неё появляется самостоятельная роль, состояние, действие или пространственная граница.
- Внутренняя DOM-обёртка без продуктового смысла отдельной зоной не становится.
- Межфункциональный результат, проходящий через несколько самостоятельных разделов S.Center, получает отдельный flow-контракт у уровня приложения.
- При выделении «Информации» или «Работ» в самостоятельную функциональную область их полный контракт переносится к новым владельцам; эта карта сохраняет только связь вкладок.
