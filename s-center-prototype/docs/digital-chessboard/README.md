# Индекс контекста «Цифровая шахматка»

**Статус:** поддерживаемый локальный маршрут функциональной области  
**Зрелость:** frontend-прототип  
**Родительский индекс:** [документация прототипа](../README.md)  
**Обновлять:** при изменении владельца, маршрута, самостоятельного документа или границы шахматки

Этот индекс является единой точкой входа в контекст функционального блока. Для локальной задачи следует читать только указанный маршрут, а не весь набор документов.

| Потребность | Основной документ | Дополнительный контекст |

## Обновление маршрута при росте

- Новое целевое правило добавляется в `functional-context.md`; план получает только локальную задачу и ссылку на правило.
- Изменение реализованного поведения обновляет `technical-baseline.md` и соответствующие проверки.
- Изменение сущности, состояния или принадлежности данных обновляет `domain-model.md`; изменение расположения или роли интерфейсной зоны обновляет `interface-map.md`.
- Новый requirement ID связывается с областью, владельцем, implementation-evidence и приёмкой в `traceability-matrix.md`, но его прогресс остаётся в активном плане.
- Новый самостоятельный контракт, например планирование или серверное сохранение факта, выносится в отдельный документ только после определения собственного владельца и регистрируется здесь.
- Если внутри области появляется дочерняя предметная директория с Markdown-документами, она получает собственный `README.md`, который регистрируется в этом индексе.
- После выполнения всех активных пунктов долговременные результаты переносятся в постоянные владельцы, а `implementation-plan.md` удаляется или архивируется согласно решению проекта. Исключённые пункты не препятствуют завершению плана.
