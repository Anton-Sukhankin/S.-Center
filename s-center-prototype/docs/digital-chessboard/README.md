# Индекс контекста «Цифровая шахматка»

Этот индекс является единой точкой входа в контекст функционального блока. Для локальной задачи следует читать только указанный маршрут, а не весь набор документов.

## Маршруты чтения

| Потребность | Основной документ | Дополнительный контекст |
|---|---|---|
| Понять согласованное целевое поведение | [Функциональный контекст](./functional-context.md) | Активный пункт плана, если изменение ещё не реализовано |
| Передать nested scroll и sticky-поведение в другой frontend-проект | [Переносимый scroll-контракт](./scroll-contract/README.md) | Пакет самодостаточен; исходники прототипа и остальные документы области downstream-агенту не требуются |
| Выбрать следующую корректировку и отметить прогресс | [План реализации](./implementation-plan.md) | Функциональный контекст и текущий baseline затронутой области |
| Понять, что реализовано сейчас и как интегрировано | [Технический baseline](./technical-baseline.md) | Исходники `src/integrations/digital-chessboard/` |
| Проверить основания решений встречи | [Реестр визуальных доказательств в плане](./implementation-plan.md#реестр-визуальных-доказательств) | Кадры в `assets/meeting-2026-08-24/` |
| Понять новые решения встречи 25.08.2026 | [Анализ дополнительной встречи](./meeting-2026-08-25-analysis.md) | Follow-up секция активного плана и кадры в `assets/meeting-2026-08-25/` |
| Подготовить или запустить аудит после корректировок | [План аудита](./post-correction-audit-plan.md) | Анализ встречи, активный план, baseline и проверяемая ревизия кода |

## Обновление маршрута при росте

- Новое целевое правило добавляется в `functional-context.md`; план получает только локальную задачу и ссылку на правило.
- Изменение реализованного поведения обновляет `technical-baseline.md` и соответствующие проверки.
- Новый самостоятельный контракт, например планирование или серверное сохранение факта, выносится в отдельный документ только после определения собственного владельца и регистрируется здесь.
- Если внутри области появляется дочерняя предметная директория с Markdown-документами, она получает собственный `README.md`, который регистрируется в этом индексе.
- После выполнения всех 27 пунктов долговременные результаты переносятся в постоянные владельцы, а `implementation-plan.md` удаляется или архивируется согласно решению проекта.
