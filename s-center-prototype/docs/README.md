## Контракт индексации

1. Корень прототипа содержит только проектный `README.md`; остальные Markdown-документы размещаются в `docs/`.
2. Каждая функциональная или проверочная область с собственными документами имеет локальный `README.md`.
3. `docs/README.md` регистрирует каждый локальный индекс первого уровня, но не дублирует его полное содержимое.
4. Локальный индекс регистрирует все Markdown-документы своей директории и указывает их состояние: текущее, целевое, временное или историческое evidence.
5. Новая область получает отдельную директорию только при появлении самостоятельного владельца контекста или как минимум двух связанных документов. До этого достаточно существующего ближайшего владельца.
6. После создания область регистрируется в машиночитаемом реестре workspace; при совпадении путей более узкая область должна быть дочерней по отношению к общей.
7. Один долговременный факт имеет одного владельца. Остальные документы дают краткое локальное следствие и ссылку.
8. После реализации целевого изменения обновляются текущий technical baseline и проверки. Завершённый временный план удаляется после переноса всех долговременных правил и evidence.
9. При перемещении или удалении документа сначала находятся входящие ссылки, затем обновляются индексы и потребители, после чего запускается `npm.cmd run check`.

## Автоматическая проверка маршрутов

`npm.cmd run check` проверяет:

- синтаксис JavaScript;
- существование всех локальных Markdown-ссылок;
- отсутствие Markdown-документов вне `README.md` в корне прототипа;
- наличие локального `README.md` в каждой документальной области;
- регистрацию документов и дочерних индексов у ближайшего владельца.

Проверка маршрутов подтверждает структуру и ссылки, но не заменяет проверку смысловой актуальности спецификации.
