# Переносимая компонентная база

## Назначение

Папка содержит автономную копию общей vanilla-компонентной базы S-Tracker и Storybook на дату, указанную в `transfer-manifest.json`. Её можно целиком перенести в другой проект, проверить отдельно и адаптировать к архитектуре проекта-получателя.

Папка не подключена к runtime, сборке или Storybook основного S-Tracker. Перенос, переименование или удаление этой копии не меняет исходную компонентную базу и интерфейсы S-Tracker.

## Состав

| Путь | Роль |
|---|---|
| `src/ui/components/` | Компоненты, публичный индекс, реестр и истории Storybook. |
| `src/styles/` | Токены, базовые стили компонентов и единая точка подключения `index.css`. |
| `src/ui/components/assets/` | PNG-иллюстрации пустых состояний. |
| `src/assets/icons/` | SVG-спрайт, используемый компонентами просмотра документа. |
| `.storybook/` | Изолированная конфигурация каталога компонентов. |
| [docs/component-library.md](./docs/component-library.md) | Снимок действующих принципов исходной базы. Это материал для адаптации, а не правило нового проекта. |
| [ADAPTATION.md](./ADAPTATION.md) | Порядок подключения и принятия решений в проекте-получателе. |

## Локальная проверка

После переноса открыть терминал в этой папке:

```powershell
npm install
npm run verify
npm run build-storybook
npm run storybook
```

По умолчанию Storybook открывается по адресу `http://127.0.0.1:6006/`.

## Использование как локального пакета

В Vite-проекте папку можно временно подключить как файловую зависимость:

```json
{
  "dependencies": {
    "@local/s-tracker-component-library-transfer": "file:../component-library-transfer"
  }
}
```

Публичные компоненты и стили подключаются отдельно:

```js
import { createButton, createSelect } from '@local/s-tracker-component-library-transfer';
import '@local/s-tracker-component-library-transfer/styles';
```

Компоненты используют DOM API и рассчитаны на браузерный runtime. Импорт SVG с суффиксом `?raw` требует Vite либо адаптации загрузки ресурса в сборщике проекта-получателя.

## Граница копии

Это самостоятельный снимок, а не синхронизируемое зеркало. Изменения в S-Tracker после даты снимка автоматически сюда не переносятся. После адаптации источником истины становится компонентная база проекта-получателя; обратная синхронизация с S-Tracker выполняется только отдельным осознанным решением.
