# Chessboard: публичный контракт

## Назначение и граница ответственности

`createChessboard` создаёт доступную матрицу «строка × колонка». Компонент владеет табличной семантикой, прокручиваемой областью, sticky-осями, roving focus, режимами выбора, легендой и визуальным представлением состояний.

Потребитель владеет предметными названиями и смыслом строк, колонок и состояний, геометрией применимых ячеек, формулами, загрузкой и сохранением данных, правами, обработкой ошибок, а также композициями с `Menu` и `Tooltip`. Эти правила не должны встраиваться в общий компонент.

## Входные данные

| Параметр | Контракт |
|---|---|
| `rows`, `columns` | Массивы `{ id, label }`. `id` уникален внутри своей оси и стабилен между обновлениями данных. |
| `cells` | Объект по ключам `createChessboardCellKey(rowId, columnId)`. Отсутствующая запись означает существующую нейтральную ячейку. |
| `states` | Массив `{ id, label, tone, pattern }`; формирует fallback-оформление и легенду. |
| `selectionMode` | `none`, `single` или `multiple`. В `none` активация остаётся доступной через `onCellActivate`, но selection-state и `aria-pressed` не создаются. |
| `selectedKeys` | Начальный выбор; неизвестные и disabled-ключи отбрасываются, в `single` сохраняется не более одного ключа. |
| `showLegend` | Показывает или скрывает легенду состояний. |
| `showCellTitle` | Управляет только нативным `title`. Доступное имя в `aria-label` сохраняется всегда; при внешнем `Tooltip` следует передавать `false`. |
| `onSelectionChange` | Получает массив выбранных позиций и `{ keys, reason, event }`. |
| `onCellActivate` | Получает `{ key, row, column, cell, selected, event }` после активации доступной ячейки. `event.currentTarget` является кнопкой ячейки и может использоваться как геометрический anchor внешнего overlay. |

Ячейка поддерживает поля `state`, `label`, `text`, `tone`, `pattern`, `appearance` и `disabled`. Допустимые значения экспортируются константами `CHESSBOARD_TONES`, `CHESSBOARD_PATTERNS`, `CHESSBOARD_CELL_APPEARANCES` и `CHESSBOARD_SELECTION_MODES`.

## Геометрия и состояния

- существующая нейтральная ячейка: `appearance: 'default'`, `disabled: false`; `state` может отсутствовать;
- физически отсутствующее пересечение: `appearance: 'absent'`, `disabled: true` и явная доступная `label`;
- недоступность нельзя выводить из отсутствия записи в `cells`: такая запись по контракту создаёт обычную нейтральную ячейку;
- `tone` и `pattern` ячейки имеют приоритет над одноимёнными значениями состояния, кроме нейтрального fallback;
- компонент не вычисляет применимость, готовность или переходы между состояниями.

## Клавиатура, выбор и runtime API

Стрелки перемещают фокус между доступными ячейками, `Home` и `End` — к первой и последней доступной ячейке текущей строки. Disabled- и absent-ячейки пропускаются. `Enter` и `Space` используют нативную активацию кнопки.

Возвращаемый контроллер предоставляет `getSelectedKeys`, `getSelectedCells`, `setSelectedKeys`, `clearSelection`, `setSelectionMode`, `setCellState`, `getCellElement` и `focusCell`. `setCellState` обновляет только визуальное состояние экземпляра и не является сохранением данных.

## Композиции

### Контекстное меню

Для действия над одной ячейкой используется `selectionMode: 'none'` и `onCellActivate`. Потребитель создаёт публичный `Menu`, позиционирует его относительно `event.currentTarget`, закрывает при scroll/resize и возвращает фокус в исходную ячейку. Кнопку ячейки нельзя передавать как `trigger` в `createMenu`, потому что `Menu` принимает владение trigger-элементом и перемещает его в свою оболочку; для позиционного overlay используется отдельный невидимый anchor. Исполняемый пример — story `CellContextMenu`.

### Tooltip

При отдельной подсказке передаётся `showCellTitle: false`, после чего внешний `Tooltip` связывается с кнопкой, полученной через `getCellElement` или событие. Задержка, содержимое и происхождение данных принадлежат потребителю. Chessboard-покрытие находится в story `WithoutNativeCellTitle`, поведение подсказки — в `Overlays/Tooltip`.

### Горизонтальное переполнение

Внутренняя область `scroll` владеет `overflow: auto`, а таблица использует `--ds-chessboard-min-width` с fallback `520px`. Потребитель может увеличить эту переменную, не создавая второй горизонтальный scroll-host. Story `HorizontalOverflow` проверяет узкий контейнер, двуосевую прокрутку и sticky-первую колонку.

## Storybook-покрытие приёмки

| Сценарий | Story |
|---|---|
| Нейтральная ячейка, четыре сплошных/диагональных состояния и absent | `NormalizedWeeklyStates` |
| Нерегулярный контур существующих и отсутствующих пересечений | `VariableGeometry` |
| Одиночный выбор | `SingleCellActions` |
| Контекстное меню и runtime-обновление одной ячейки | `CellContextMenu` |
| Внешний tooltip без нативного `title` | `WithoutNativeCellTitle` + `Overlays/Tooltip` |
| Горизонтальное переполнение | `HorizontalOverflow` |
| Дополнительные библиотечные режимы | `MultipleSelection`, `RuntimeCellUpdate`, `Empty` |
