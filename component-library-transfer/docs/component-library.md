# Общая компонентная база S-Tracker

## Назначение

`src/ui/components/` — единственный источник переиспользуемых UI-контролов и базовых паттернов текущего vanilla/Vite-прототипа. Разделы `Задачи`, `Документы`, `Поиск` и `Шаблоны документов` используют общие реализации, но сами владеют продуктовыми данными, условиями доступности действий и результатами пользовательских сценариев.

Этот документ не повторяет API каждого компонента и не хранит копию текущего реестра. Актуальный состав, идентификаторы, модули и потребители находятся в `src/ui/components/registry.js`; исполняемые состояния находятся в Storybook.

## Источники истины

| Что нужно проверить | Источник |
|---|---|
| Компонент существует и доступен для повторного использования | `src/ui/components/registry.js` |
| Публичные экспорты компонентной базы | `src/ui/components/index.js` |
| Фактическое поведение и API компонента | Модуль, указанный в записи `registry.js` |
| Визуальные и интерактивные состояния | Соответствующий `*.stories.js` в `src/ui/components/` |
| Общие токены и стили | `src/styles/base/tokens.css`, `src/styles/components/core-ui.css`, `src/styles/components/component-library.css` |
| Настройка каталога компонентов | `.storybook/` |
| Продуктовое условие, значение и результат | Комплект затронутого компонента в `docs/components/` |

Если описание в этом файле расходится с реестром или модулем, использовать реестр и модуль, затем исправить этот документ только в части устойчивого правила.

## Правила использования

1. Перед созданием кнопки, chip, поля, селекта, мультивыбора, чекбокса, переключателя, вкладок, таблицы, дерева, пагинации, drawer, modal, alert, toast или пустого состояния агент проверяет `registry.js`.
2. Feature-модуль импортирует существующий компонент из `src/ui/components/` или через `@s-tracker/ui`; локальная копия общей разметки и CSS не создаётся.
3. История Storybook импортирует реальный компонент. Копия разметки компонента внутри истории не считается проверкой runtime.
4. Общий компонент хранит только собственное локальное UI-состояние. Фильтрация, поиск, состав колонок, массовые операции, сохранение продуктового черновика и другие сценарии остаются в feature-модуле.
5. Продуктовая спецификация фиксирует условие S-Tracker и видимый результат, но не повторяет props, обработчики, DOM, CSS-классы и стандартную механику общего компонента.
6. Локальный аналог допустим только после проверки, что в реестре нет подходящего компонента или требуемого варианта. Если создаётся новый общий компонент, он добавляется в реестр, публичные экспорты и Storybook в той же задаче.

## Устойчивые интерактивные контракты

| Компонент | Правило общей базы | Допустимая адаптация потребителя |
|---|---|---|
| `MultiSelect` | Клик по основной области или кнопке раскрытия переключает открытое и закрытое состояние dropdown. Кнопка общей очистки видна только при наличии хотя бы одного выбранного доступного значения; при пустом выборе она отсутствует. Кнопки удаления значения и очистки выполняют только собственное действие. | Feature-модуль передаёт варианты и выбранные значения, но не заменяет механику переключения dropdown или видимость очистки локальным обработчиком. |
| `Alert` / `Toast` | `success` показывается только после завершённого изменения данных или состояния; `info` — при открытии следующего интерфейса, подготовке действия или сообщении без изменения данных; `error` — при неуспешной операции или отклонённом подтверждении из-за ошибки. Ошибка использует `role="alert"`, остальные варианты — `role="status"`. | Компонент-потребитель определяет фактическое условие и текст результата. Цвет не используется как единственный носитель смысла: сообщение всегда содержит текст. |
| `Resize Handle` | Перетаскивание меняет размер в пределах, заданных потребителем; двойной клик и клавиша `Home` возвращают базовое значение. Стрелки изменяют размер на обычный шаг, `Shift` со стрелкой — на увеличенный шаг. | Feature-модуль задаёт ориентацию, направление, базовое, минимальное и максимальное значения, применяет размер к своей области и не создаёт локальный обработчик сброса. |

## Связанное обновление

| Изменение | Что проверить и при необходимости обновить |
|---|---|
| Добавлен, удалён или переименован общий компонент | `registry.js`, `index.js`, модуль, истории и импорты потребителей |
| Изменён публичный API или локальное состояние общего компонента | Модуль, истории и все потребители из `registry.js` |
| Изменился список фактических потребителей | Поле `consumers` в `registry.js`; таблицу-дубликат в документации не создавать |
| Изменение общего компонента меняет видимое продуктовое поведение | `01/02/03` затронутых продуктовых компонентов и связанный flow по матрице из `docs/documentation-standards.md` |
| Изменение является внутренним и не меняет видимый результат | Компонентные спецификации и flow не менять; при переносе файлов обновить `docs/component-code-map.md` |

## Проверка

| Команда | Что подтверждает |
|---|---|
| `npm run build-storybook` | Истории импортируют рабочие компоненты и собираются без ошибки. |
| `npm run build` | Основной runtime собирается с текущими потребителями. |
| `npm run docs:check` | Документация не содержит структурных нарушений и битых локальных ссылок. |

Подключение React, Tend UI, Material UI, корпоративной дизайн-системы или новой зависимости выполняется только по отдельной прямой команде пользователя.
